## 0. 硬规则

### 0.1 第一次收到指令：先看，别动手

**新对话第一次收到指令时，只允许「查看 / 熟悉项目」，不允许对文件做任何修改。**

- 可以：读文件、`ls`、`git status` / `git log`、`grep`、看 Gradle 与源码结构、看 `docs/`。
- 不可以：Write / Edit / 新建 / 删除 / 移动 / 格式化 / 提交 / 推送 / 跑构建产出文件。
- 熟悉完就**停下来**，说清楚「项目是什么、当前状态如何、有哪些待办」，然后**等用户进一步指示**。
- 这条优先于任何「看起来顺手该做掉」的事。

### 0.2 正式工作流（用户 2026-10-26 定，必须遵守）

1. **用户提要求** → 我**复述理解并确认**（要做什么、边界、影响面、有歧义的地方先问清）。
2. 用户确认、明确说「开工」之后，我才动代码。
3. 一直做到 **`gradlew assembleDebug` 编译通过**，然后**把 APK 文件夹打开给用户**，并且**选中 apk 文件**
   （只打开目录容易让人找不到是哪个包）。**必须用 PowerShell**，别用 Git Bash 调 `explorer.exe` ——
   路径带空格时它会静默失败或落到「文档」之类的目录：
   ```powershell
   $apk = 'D:\project\android\wherever play\app\build\outputs\apk\debug\app-debug.apk'
   Test-Path $apk                       # 必须 True，再往下走
   Start-Process explorer.exe -ArgumentList "/select,`"$apk`""
   ```
   顺手打印一下 APK 的大小与时间，证明打开的是刚编出来的那个包。
4. **测试由用户自己做**：用户装到模拟器上验，再把结果反馈给我。
   **我不要操作模拟器** —— 不跑 `mumu-android-ops`、不 `adb install`、不自己截图取坐标。
   （历史上装过、事件驱动地点过界面，现在一律不做。）
5. 本次会话的改动**写进 `docs/开发日志.md`**，不要写进本文件。

## 二、已经定死、别再讨论的决策

1. 音频 **mp3/wav/flac**，谱面 **PDF**，单曲 ≤ 30 分钟（导出成图片会爆内存，不考虑）。
   **音频自 0.3.0 起可选**：没有音频就是「纯谱面项目」，时间轴固定 12:00。
2. 打点页**页序严格递增**，不允许倒序打点；**第 1 页固定 0:00**，锚点锁死；相邻打点**最小间隔 300ms**。
3. **不做波形轨道**、**变速播放永久取消**（用户明确）。
4. 液态玻璃**只在主界面**用，其他页纯色 + 半透明，避免低端机掉帧。
5. 播放页是**电子书式全屏**：只留进度条 + 播放/暂停，左右滑动翻页；手动翻页不影响音频。
6. 存储先用 **JSON 不用 Room**（接口已隔离，随时可换）。
7. 播放用 **MediaPlayer 不用 Media3**，这是终态。**后台播放 / 通知栏已舍弃**，别为它引入 Media3；
   演出靠 `keepScreenOn`（默认开）。
8. 风格标签、`Intent` 打开 `.wplay`（E5）均已舍弃；`.wplay` 唯一入口是 App 内「＋ → 导入」，
   `AndroidManifest.xml` 保持只有 launcher 一个 intent-filter。
9. 详情页**只读 + 播放**，所有改动项目的动作都在编辑页；换音频/换谱面**不清空打点**（0.2.1 起）。
10. **别加 Android 12+ SplashScreen**（实测启动反而变慢，工程里加过又全删了）。

## 二·附、数据与打包（几条不变式）

- **`updatedAt` 集中盖章**：内容真被改过才刷新（首页「最近修改」的唯一依据），统一走
  `AppRoot.stampUpdate`，别在修改点手工赋值；点进去看 / 播放 / 导出**不算**修改。
  `createdAt / lastOpenedAt / updatedAt` 是设备本地属性，**不进 `.wplay`**。
- **`.wplay` / `.wplist`** = ZIP（`manifest.json` + `media/`）。项目导出自包含（音频+谱面+封面）；
  播放列表导出**内嵌所有可用项目**（只存 id 到别人手机上必然全是失效项）。
- **导入保留原 id** —— 这是播放列表「不可用」占位能自动恢复的前提，别改成重新分配。
- `manifest.version` **保持 1**：纯加可选字段不升版本（升了旧 App 会直接拒收新文件），
  新 App 读老文件靠 `opt*` 默认值；`version > 1` 直接拒收并提示「来自更新版本的 App」。
- `tag` / `bpmX10` / `firstBeatMs` 全部**可选**，老数据缺键按 null 处理，**不写迁移脚本**。
  BPM 存 ×10 整数（`120.5 → 1205`），避免 `120.29999…` 这类浮点脏值。
- **`manualTurn` 是三态**（`Project` 与 `Playlist` 同构）：`null` = 跟随设置页的全局默认，
  `true/false` = 在播放页左下角单独设置过。它是**播放偏好不是内容**：`stampUpdate` 里要像
  时间字段那样排除掉，否则拨一下开关这个项目就会窜到「最近修改」第一位。
- **新建项目完成不再自动进打点页**（0.2.2 用户明确），回首页列表。
- **项目可以没有音频**（0.3.0）：`audioFile: String?`，null = 纯谱面项目。
  - 无音频时 `durationMs` 一律写 `Project.DEFAULT_DURATION_MS`（**12:00**），打点、进度条、打点页都按它算；
    播放页跑的是**静音时间轴**（不初始化 MediaPlayer，位置按真实流逝时间推进），到打点照常翻页。
  - 「移除音频」用 `MarkRules.clampToDuration` 收打点：**一页不删**，超过 12:00 的压进 12:00 内。
  - 存储/打包的兼容口径：空串或缺键 = 没有音频；`durationMs = 0` 按 12:00 兜底；
    `manifest.version` 仍是 1（老文件缺 `audio` 不再报错）。
  - **新建项目的名字默认取 PDF 文件名**（不是音频名），用户手动改过就不再自动覆盖。
- 动效参数统一在 `ui/WpMotion.kt`（翻页 220ms / 回弹 160ms / 控制栏 180ms / 按压 90-140ms）。

## 三、UI 硬约束（用户点名过，别改回去）

- **视觉可以小于 44，热区必须 ≥ 44**；新按钮一律套 `WpTapArea`（自带 44 热区 + 按压 scale 0.96）。
- 主操作一屏只有一个：实心 `#EDEDED` 底 / `#17171A` 字（播放键 / 打点页完成 / 首页新建）。
- 首页两个「＋」**只留图标不写文字**；筛选/排序选中项**不打钩**，只靠强调色 + Medium 字重。
- 「未打点」角标在封面**左上角**、乐器标签在**左下角**、`⋮` 在封面**右下角**浮层、★ 独占作者行行尾。
- 返回一律 `IconBack(tint, 18.dp)`，全工程没有文字形态的返回。
- 播放页上/下一首**只在播放列表时渲染**（单曲时整组不渲染，不是置灰）；进度条上的打点只做**竖线提示**，
  不参与命中；提前量在 `⋮ → 翻页提前量` 弹窗里（不在底部）。
- 播放列表首页**点整行 = 直接开播**，编辑页唯一入口是 `⋮ → 编辑`。
- 长列表都要有 `WpScrollBar`（24dp 触摸带，行域像素精度）；把它和 pager/手势的关系改动前先看踩坑表。

## 四、踩坑表（改代码前扫一眼）

| 坑 | 正解 |
|---|---|
| PdfRenderer 位图格式 | 目标 Bitmap **必须 ARGB_8888**，RGB_565 直接抛异常（表现为全黑 + 「渲染 3ms」） |
| PDF 缓存预算 | 按「一页字节数」算，别按页数估；现在 48MB(API≥26)/20MB，单页封顶 12MB，渲染后校验当前页还在不在缓存里 |
| 谱面尺寸 | 渲染宽度 = `min(可用宽, 可用高 × 页面宽高比)`，再由字节预算封顶；**别按固定 400dp** |
| `pointerInput` 的 key | 高频变化的 state **绝不能当 key**，用 `Unit` + `rememberUpdatedState` |
| 共用资源的 `DisposableEffect` | 渲染线程池 / renderer 不能挂在随数据变化的 effect 上，拆独立 effect |
| `LocalContentColor` | 深色底上文字发黑 → 根节点包 `Surface(color=bg, contentColor=onBg)` |
| 翻页黑屏 | 三页并排跟手 + 渲染器提到页面级共用，绘制一律走缓存 |
| 手势漏 `onDragCancel` | 手势被系统抢走不走 `onDragEnd`，位移会永久留着；三个出口都归位 `clearPageOffset()` |
| `animate()` 被取消 | 协程被下一次翻页打断会抛 `CancellationException`，`finally` 里必须复位 |
| 视窗跟随 + 手指反算时间 | 拖动期间**冻结视窗**，1px 恒等固定时长，否则正反馈失控 |
| `while (isPlaying)` 里写衔接 | 播放列表播完会卡死，用**显式曲间遮罩状态机**；`autoAdvanceMs <= 0` 单独分支 |
| 播放循环捕获旧 player | 循环 key 要带 `project.id`，player/时长用 `rememberUpdatedState`；切歌置 `switching` 抑制误判 |
| MediaPlayer 时长 | `durationMs` 必须 `load()` **之后**读，写在 `remember(player){}` 里永远是 0 |
| 打点预览跟着光标走 | 预览页 = 选中圆点的页，没选中才跟光标；一按播放清掉选中 |
| 自适应图标 | 前景要缩到 **72/108** 居中放进 108dp 画布；**不要建 `mipmap-anydpi/`**（无 v26），会盖住密度 PNG 和自适应 |
| ripple 灰方框 | Material 默认 ripple 按**矩形热区**画。唯一解法：`clip(shape)` 写在 `clickable` **之前**，并传**视觉**尺寸（不是 44 热区）；本工程收进 `WpTapArea(rippleShape = …)` |
| `HorizontalPager` 跨页跳卡住 | 别按 `currentPage` 实时回写 tab（中途经过第 1 页会取消滚动动画），只认「滚动停稳」，且用 `rememberUpdatedState(tab)` |
| 滚动条滑块偏下 / 拖到底跑出去 | 容器对齐必须 `TopEnd`（`CenterEnd` 会先垂直居中再叠加 offset，多走半个差） |
| 滚动条抽搐/一格一格蹦 | 按下冻结分母与滑块长度、拖动期间滑块直接跟手指、增量拖动、松手延迟 120ms 交还；seek 用**亚项精度**（`stridePx`） |
| 网格滚动位置 | 滚动位置属于**行域**，item 索引不是行索引：`rows = ceil(total/列数)`，`index = row × 列数`，永远取行首；`stridePx` 要跳过同行的其他列 |
| 拖到底还差一截 | 「能滚多远」必须算上 `contentPadding`（首页底部 110dp 给浮动栏） |
| 拖动排序 | 别按位移反推目标行，**边拖边换位**（越过半行就真换一格并减掉一整行） |
| 全屏看图里点按钮把图关了 | 关闭手势挂在根 Box，子级必须套 `WpTapArea`/`clickable`，裸 `Text` 会冒泡上去 |
| 写相册的权限 | `MediaStore`+`RELATIVE_PATH` 从 API 29 才有；24–28 走 `WRITE_EXTERNAL_STORAGE`（`maxSdkVersion="28"`）；Q+ 插入时 `IS_PENDING=1`，写完必须 update 成 0 |
| Kotlin 局部函数 | 前向引用编译报错：内联，或提到外面 |
| material-icons | 依赖不存在，**全部自绘 Canvas 图标**（`WpIcons.kt`） |
| 看到 `private` 报 local function | 症状不是原因：往上找漏掉的 `}`（函数没闭合，后面的顶层声明全被当成局部函数） |
