## 二、已经定死、别再讨论的决策

1. 音频 **mp3 / wav / flac**，谱面 **PDF**，单曲时长 ≤ 30 分钟（导出成图片会爆内存，不考虑）。
2. 打点页 **页序严格递增**，不允许倒序打点。
3. **第 1 页固定 0:00**，锚点锁定不可拖。
4. 相邻打点**最小间隔 300ms**。
5. **不做波形轨道**（用户明确取消）。
6. **变速播放永久取消**（会影响时间轴对齐，坑太深）。
7. 液态玻璃效果**只在主界面**用，其他页用纯色 + 半透明，避免低端机掉帧。
8. 播放页是**电子书式全屏**：只保留进度条 + 播放/暂停，左右滑动翻页，手动翻页不影响音频，下个打点自动跳回。
9. 存储先用 **JSON** 不用 Room；接口已隔离，随时可换。
10. 播放用 **MediaPlayer** 不用 Media3（后台播放要单独一轮做）。

## 三、0.1.0 新增功能（2026-10-25）

### 1. 乐器标签（单选）

| 项 | 做法 |
|---|---|
| 数据 | `Project.tag: String?`，JSON 里存 `"tag"`；老数据没有这个键 → `optString` 拿到 `""` → 存成 null，不需要迁移脚本 |
| 标签库 | `data/TagStore.kt`。**内置 8 个不落盘**（人声/电吉他/木吉他/贝斯/鼓/键盘/尤克里里/其它），自建的存 `SharedPreferences("wp_tags")` 一段换行分隔文本 |
| 上限 | `TagStore.MAX = 20`（内置 + 自建一起算，即最多再自建 12 个）。到上限后「新建标签」按钮直接禁用 |
| 入口 | 项目详情 → 「乐器标签」行 → `TagPickerDialog`（固定 3 列，避免 FlowRow 的实验 API） |
| 展示 | 首页卡片**封面左下角**角标（`0xB3121216` 底 + `#9EC5FF` 字）；「未打点」在左上角，两者分居两角 |
| 筛选 | 首页右上角漏斗 → 只列「真的有项目在用」的标签 + 「全部乐器」。激活时漏斗图标变强调色，筛选行末尾多出一个 `标签 ✕` 胶囊，点它取消 |

> 风格标签**已舍弃**（用户 2026-10-25 明确）。`TagStore` 里没有分类概念，将来要做风格就得再加一层分类。

### 2. `.wplay` / `.wplist` 打包格式

```
manifest.json          format / version / exportedAt + project(或 playlist+projects)
media/audio-xxx.mp3
media/pdf-xxx.pdf
media/cover-xxx.jpg
```

- 项目导出**自包含**（音频 + 谱面 + 封面全带上）；播放列表导出会把**所有可用项目一起内嵌**——
  只存 id 的话文件到别人手机上必然全是失效项。
- **导入保留原 id**（本机没被占用时）。这是 `Playlist` 里「不可用」占位能自动恢复的前提：
  删了项目再重新导入同一个 `.wplay`，播放列表里那一条会自己接上。
- 单个导出走 `CreateDocument`（另存为，文件名 `<名称>.wplay`）；多选导出走 `OpenDocumentTree`，
  用 `DocumentsContract.createDocument` 逐个写（不走 FileProvider / ACTION_SEND_MULTIPLE）。
- 导入共用一个入口（`OpenDocument("*/*")`），按 `manifest.format` 分派，导入完弹一句提示条。
- `manifest.version > 1` 直接拒绝，提示「来自更新版本的 App」。

### 3. 卡片菜单与页面拆分

- 卡片右下角 `⋯` 不再直跳详情，而是 `DropdownMenu`：**详情 / 编辑 / 导出 / 删除**。
- `Route.Detail / Edit / Mark` 只带 **id**，页面内每次从 `projects` 现查 —— 改完名字立刻刷新，
  不会像以前那样要在 `route` 里手动回写一份新副本。
- **详情页**（`ProjectDetailScreen`）：**只读信息 + 播放**。统计信息、改名称/作者（弹窗）、改标签（弹窗）、
  点封面换图，主操作只有「播放」一个实心。底部不再放任何管理按钮（见下一行）。
- **编辑页**（`ProjectEditScreen`）：所有会改动项目的动作都在这。上半是**动文件**——更换歌曲 /
  更换谱面 / 重新打点，三个都会清空打点，各自过确认弹窗；下半「其它操作」是**导出 .wplay / 删除项目**
  （删除会提示被几个播放列表引用）。
  > 2026-10-25 调整：详情页底部原来还挂着「更换文件 / 重新打点」「导出 .wplay」「删除项目」三个按钮，
  > 和右上角「编辑」入口重复，已全部下放到编辑页。

### 4. 导入入口与批量操作

- 两个首页右上角 `＋` 都改成下拉：**新建 / 导入**（项目页是 `.wplay`，列表页是 `.wplist`，但两个入口都接受任意一种，按内容分派）。
- 项目页长按多选：收藏 / 导出 / 删除；播放列表页长按多选：导出 / 删除。
- `AppRoot` 里加了一条 **toast**（底部浮层，2.6 秒自动消失），导入/导出的结果都走它。

## 四、UI 改版（2026-10-25 已落地）

按 `ui/Wherever Play · 按钮分布与交互动画改版.pdf` + `ui/work/…开发对照.md` 重排了四个页面。
**只改布局与动效，没改美术风格**（颜色/玻璃/圆角全部沿用 `Theme.kt`）。

三条分布原则（后面加按钮先看这个）：

1. **主操作一屏只有一个** —— 实心 `#EDEDED` 底 / `#17171A` 字只给最高频那个动作
   （播放页 = 播放键；打点页 = 完成；首页 = 新建）。
2. **次操作并列但不抢戏** —— 玻璃填充（白 8%~15%）+ 0.5dp 描边；同一条视觉带最多 3 个。
3. **低频与破坏性动作移出主视觉带** —— 重新打点/返回列表进「更多」，删除独占一个图标位。

统一约束：**视觉可以小于 44，热区必须 ≥ 44**。`WpIconButton` 已经是「44 容器 + 34 视觉」，
新写的按钮一律套 `WpTapArea`（自带 44 热区 + 按压 scale 0.96）。

### 用户明确点名的几处（别再改回去）

| 要求 | 实现 |
|---|---|
| 播放页上/下一首**只在播放列表时生效** | `multi = queue.size > 1`；单曲时整组**不渲染**（不是置灰），由 `SpaceBetween` 让播放键回到正中 |
| 播放页进度条**打点只做竖线提示** | `WpProgress.tick`（白 55%）画 1.5dp 竖线、9dp 高；**不参与命中**，整条只有「按位置 seek」一种交互 |
| 竖线对比度**不要太强也不要太弱** | 轨道白 18% → 竖线白 55% → 已播段 `#D9DCE3`。三层拉开但竖线不满白 |
| 首页「未打点」**不占作者位置** | 移到封面**左上角**角标（`0xB3121216` 底 + `#F0C070` 字） |
| 首页卡片右下角**三个点靠太近** | `⋮` 搬到封面**右下角浮层**（32 热区 + 半透明暗底，浅色封面也看得清），★ 独占作者行行尾（44 热区 + 20 图标） |

### 各页现在的结构

- **播放页**：顶栏 56（返回 / 标题组 / 更多 4 项）→ 谱面撑满 → 底部两行：进度行（`2:14 ——●—— 5:29`，
  打点竖线）+ 控制行（`上一首 播放 下一首 … − 值 ＋`）。仪表盘默认关，从「更多」开。
  提前量：单击 ±100ms，长按 100ms 连发（首延迟 300ms），松手吸附 50ms 网格，点数值直接输。
- **打点页**：顶栏 56（完成按 `validate` 结果在实心/玻璃之间切）→ 预览 → 工具行 44（撤销/重做 … 选中胶囊+取消）
  → 播放行 36 → 微调行 40（选中才出现）→ 时间轴 116 → 底栏（添加第 N 页占 2/3 带页码色点，更多固定 104）。
- **首页**：标题撑满 + 排序 44 圆 + 「＋ 新建」玻璃胶囊；网格 **`GridCells.Fixed(2)`**
  （原来 `Adaptive(168)` 在 360dp 屏算出来是 1 列，这才是「整屏巨幅方块」的根因）。
- **播放列表行**：长按整行拖动排序（拖动中抬升 + 跟手位移，松手才换位），把手是纯视觉提示，
  右侧只留一个删除图标，行内可点区域 5 → 3。
- **底栏 tab**：选中块用 `spring(0.82, 380)` 在胶囊内滑动，文字色 180ms 过渡。

### 动效参数都在 `ui/WpMotion.kt`

翻页 220ms `(0.2,0,0,1)` / 回弹 160ms；控制栏 180ms `(0.4,0,0.2,1)` + 上移 4dp；
按压 90ms 进 / 140ms 回；底栏 320ms spring；曲间遮罩 200ms 淡入 + 倒计时每秒脉冲 1.0→1.06→1.0。

## 五、踩过的坑（改代码前务必扫一眼）

| 坑 | 症状 | 正解 |
|---|---|---|
| PdfRenderer 位图格式 | PDF 全黑但仪表盘显示"渲染 3ms" | 目标 Bitmap **必须 `ARGB_8888`**，`RGB_565` 直接抛异常 |
| `pointerInput` 的 key | 拖动中断 / 按钮点不动 | 高频变化的 state **绝不能当 key**，用 `Unit` + `rememberUpdatedState` |
| 共用资源的 `DisposableEffect` | 切歌后永远"正在渲染第 1 页" | **共用资源（渲染线程池、renderer）不能挂在随数据变化的 effect 上**，拆成独立 effect |
| `LocalContentColor` | 深色背景上文字发黑 | 根部包一层 `Surface(color=bg, contentColor=onBg)` |
| 翻页黑屏 | 翻页瞬间闪一下/黑一下 | 三页并排跟手模型 + 渲染器提到页面级共用，绘制时一律从缓存取图 |
| 视窗跟随 + 手指反算时间 | 放大后拖光标失控（正反馈） | **拖动期间冻结视窗**，1px 恒等固定时长 |
| `while (isPlaying)` 里写衔接 | 播放列表播完卡死 | 用**显式曲间遮罩状态机**，别把逻辑塞进播放循环 |
| 0 秒自动衔接 | 倒计时 0 秒不走 | `autoAdvanceMs <= 0` 单独分支直接切歌，不进倒计时循环 |
| Kotlin 局部函数 | 前向引用编译报错 | 内联，或提到外面 |
| material-icons | 依赖不存在 | 全部自绘 Canvas 图标 |
| 播放循环捕获旧 player | 播放列表里点下一首，跳过去却停在**上一首的总时长**处（暂停时正常） | 循环的 key 要带 `project.id`，player / 时长用 `rememberUpdatedState` 读；切歌时置 `switching` 标记抑制「播完」误判。三者缺一都会复现 |
| MediaPlayer 时长读太早 | 进度条总长永远等于导入时记录的 `project.durationMs` | `durationMs` 必须 **`load()` 之后**读；写在 `remember(player){…}` 里永远是 0 |
| 打点预览跟着光标走 | 点小圆点想看那一页，预览却停在光标页 | 预览页 = 选中圆点的页，没选中才跟光标；一按播放就清掉选中（否则播放时谱面被钉住） |
| 360dp 机型的控制行 | 播放键居中后和提前量组压在一起 | 一行放不下「2×44 + 56 + 提前量 124」还要居中，多曲时把提前量组挪到进度行右端（控制区 100→112） |
| PDF 缓存预算按密度算错 | **高密度手机**上谱面只剩一条边、左边一片黑、占位文字「正在渲染第 N 页…」永远不消失；同版 APK 在平板上正常 | 24MB 是按 3.3MB/页估的（400dp、密度 2），密度 3 时一页就 8.1MB，**三页并排正好把当前页挤出缓存**，而挤掉后没有任何东西会再触发它渲染。现在 48MB(API≥26)/20MB，且每次预渲染后校验当前页还在不在，不在就补渲染一次；渲染失败也会写 `DebugStats.renderError`，不再假死成「正在渲染…」 |
| `detectHorizontalDragGestures` 漏 `onDragCancel` | 谱面整体偏到一边，只露出相邻页的一条边（像渲染错位） | 手势被系统抢走时**不会**走 `onDragEnd`，`dragOffset` 会永久留着。三个出口（松手 / 取消 / 动画被打断）都要归位，统一走 `clearPageOffset()` |
| `animate()` 被取消 | `animating=true` 卡住 + 半个屏的偏移 | 翻页动画的协程被下一次翻页打断会抛 `CancellationException`，必须在 `finally` 里复位；关闭翻页动画的分支也要清 |
| 拖动排序「按位移反推目标行」 | 拖到两首之间，松手却跳到最上面 | 位移/行高 的取整对密度和行高极敏感。改成**边拖边换位**：越过半行就真换一格并把位移减掉一整行，目标位置由换位次数决定，不再做除法 |
| 新建项目没有标签入口 | 新建出来的项目标签一律「未设置」，首页角标空着 | 新建页当时只做了名称/作者。补一个「乐器标签」按钮复用 `TagPickerDialog` |

## 六、测试方式

MuMu 模拟器**没有开放 adb 端口**，所以：

1. 改完代码，让我跑 `gradlew assembleDebug` 出 APK。
