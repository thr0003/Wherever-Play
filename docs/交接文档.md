## 二、已经定死、别再讨论的决策

1. 音频 **mp3 / wav / flac**，谱面 **PDF**，单曲时长 ≤ 30 分钟（导出成图片会爆内存，不考虑）。
2. 打点页 **页序严格递增**，不允许倒序打点。
3. **第 1 页固定 0:00**，锚点锁定不可拖。
4. 相邻打点**最小间隔 300ms**。
5. **不做波形轨道**（用户明确取消）。
6. **变速播放永久取消**（会影响时间轴对齐，坑太深）。
7. 液态玻璃效果**只在主界面**用，其他页用纯色 + 半透明，避免低端机掉帧。
8. 播放页是**电子书式全屏**：只保留进度条 + 播放/暂停，左右滑动翻页，手动翻页不影响音频，下个打点自动跳回。
9. 存储先用 **JSON** 不用 Room；接口已隔离，随时可换。
10. 播放用 **MediaPlayer** 不用 Media3，**这是终态**。后台播放 / 通知栏**已舍弃**（2026-10-25 用户明确），
    不用再为它引入 Media3；演出场景靠 `keepScreenOn`（默认开）保证屏幕不熄。

### 1. 乐器标签（单选）

| 项 | 做法 |
|---|---|

| 展示 | 首页卡片**封面左下角**角标（`0xB3121216` 底 + `#9EC5FF` 字）；「未打点」在左上角，两者分居两角 |
| 筛选 | 首页右上角漏斗 → 只列「真的有项目在用」的标签 + 「全部乐器」。激活时漏斗图标变强调色，筛选行末尾多出一个 `标签 ✕` 胶囊，点它取消 |

> 风格标签**已舍弃**（用户 2026-10-25 明确）。`TagStore` 里没有分类概念，将来要做风格就得再加一层分类。

### 2. `.wplay` / `.wplist` 打包格式

```
manifest.json          format / version / exportedAt + project(或 playlist+projects)
media/audio-xxx.mp3
media/pdf-xxx.pdf
media/cover-xxx.jpg
```

- 项目导出**自包含**（音频 + 谱面 + 封面全带上）；播放列表导出会把**所有可用项目一起内嵌**——
  只存 id 的话文件到别人手机上必然全是失效项。
- **导入保留原 id**（本机没被占用时）。这是 `Playlist` 里「不可用」占位能自动恢复的前提：
  删了项目再重新导入同一个 `.wplay`，播放列表里那一条会自己接上。
- 单个导出走 `CreateDocument`（另存为，文件名 `<名称>.wplay`）；多选导出走 `OpenDocumentTree`，
  用 `DocumentsContract.createDocument` 逐个写（不走 FileProvider / ACTION_SEND_MULTIPLE）。
- 导入共用一个入口（`OpenDocument("*/*")`），按 `manifest.format` 分派，导入完弹一句提示条。
- `manifest.version > 1` 直接拒绝，提示「来自更新版本的 App」。

### 3. 卡片菜单与页面拆分

- 卡片右下角 `⋯` 不再直跳详情，而是 `DropdownMenu`：**详情 / 编辑 / 导出 / 删除**。
- `Route.Detail / Edit / Mark` 只带 **id**，页面内每次从 `projects` 现查 —— 改完名字立刻刷新，
  不会像以前那样要在 `route` 里手动回写一份新副本。
- **详情页**（`ProjectDetailScreen`）：**只读信息 + 播放**。统计信息、改名称/作者（弹窗）、改标签（弹窗）、
  点封面换图，主操作只有「播放」一个实心。底部不再放任何管理按钮（见下一行）。
- **编辑页**（`ProjectEditScreen`）：所有会改动项目的动作都在这。上半是**动文件**——更换歌曲 /
  更换谱面 / 重新打点，三个都会清空打点，各自过确认弹窗；下半「其它操作」是**导出 .wplay / 删除项目**
  （删除会提示被几个播放列表引用）。
  > 2026-10-25 调整：详情页底部原来还挂着「更换文件 / 重新打点」「导出 .wplay」「删除项目」三个按钮，
  > 和右上角「编辑」入口重复，已全部下放到编辑页。

### 4. 导入入口与批量操作

- 两个首页右上角 `＋` 都改成下拉：**新建 / 导入**（项目页是 `.wplay`，列表页是 `.wplist`，但两个入口都接受任意一种，按内容分派）。
- 项目页长按多选：收藏 / 导出 / 删除；播放列表页长按多选：导出 / 删除。
- `AppRoot` 里加了一条 **toast**（底部浮层，2.6 秒自动消失），导入/导出的结果都走它。

## 四、UI 改版（2026-10-25 已落地）

按 `ui/Wherever Play · 按钮分布与交互动画改版.pdf` + `ui/work/…开发对照.md` 重排了四个页面。
**只改布局与动效，没改美术风格**（颜色/玻璃/圆角全部沿用 `Theme.kt`）。

三条分布原则（后面加按钮先看这个）：

1. **主操作一屏只有一个** —— 实心 `#EDEDED` 底 / `#17171A` 字只给最高频那个动作
   （播放页 = 播放键；打点页 = 完成；首页 = 新建）。
2. **次操作并列但不抢戏** —— 玻璃填充（白 8%~15%）+ 0.5dp 描边；同一条视觉带最多 3 个。
3. **低频与破坏性动作移出主视觉带** —— 重新打点/返回列表进「更多」，删除独占一个图标位。

统一约束：**视觉可以小于 44，热区必须 ≥ 44**。`WpIconButton` 已经是「44 容器 + 34 视觉」，
新写的按钮一律套 `WpTapArea`（自带 44 热区 + 按压 scale 0.96）。

### 用户明确点名的几处（别再改回去）

| 要求 | 实现 |
|---|---|
| 播放页上/下一首**只在播放列表时生效** | `multi = queue.size > 1`；单曲时整组**不渲染**（不是置灰），由 `SpaceBetween` 让播放键回到正中 |
| 播放页进度条**打点只做竖线提示** | `WpProgress.tick`（白 55%）画 1.5dp 竖线、9dp 高；**不参与命中**，整条只有「按位置 seek」一种交互 |
| 竖线对比度**不要太强也不要太弱** | 轨道白 18% → 竖线白 55% → 已播段 `#D9DCE3`。三层拉开但竖线不满白 |
| 首页「未打点」**不占作者位置** | 移到封面**左上角**角标（`0xB3121216` 底 + `#F0C070` 字） |
| 首页卡片右下角**三个点靠太近** | `⋮` 搬到封面**右下角浮层**（32 热区 + 半透明暗底，浅色封面也看得清），★ 独占作者行行尾（44 热区 + 20 图标） |
| 两个首页右上角「＋」**不许写「新建」** | `WpPillAction(text = "")`，只剩图标；下拉里的「新建项目 / 导入」文案保留 |
| 筛选与排序**选中不许打钩** | 去掉「✓ 」前缀，只靠强调色 + Medium 字重 |
| 点封面 = **看大图**，不是换图 | 详情页 → `ImageViewerOverlay`；换图挪进全屏页的「更换图片」 |
| 长列表要有**可上下拖的滑块** | `WpScrollBar`：24 触摸 / 4 视觉，按下即跳 + 跟手，装得下就不出现 |
| 返回图标**全工程统一细 chevron** | 一律 `IconBack(tint, 18.dp)` + `visual = 0.dp`；已无文字形态的返回 |

### 各页现在的结构

- **播放页**：顶栏 56（返回 / 标题组 / 更多 **5** 项）→ 谱面撑满 → 底部两行：进度行（`2:14 ——●—— 5:29`，
  打点竖线）+ 控制行（单曲 = 居中播放键；播放列表 = `上一首 播放 下一首` 对称分居两侧）。
  **两种模式布局完全一致，唯一差别就是上/下一首按钮**（进度行 22dp、控制区 100dp 一套走完）。
  仪表盘默认关，从「更多」开。
  **提前量已不在底部**（2026-10-25）：走 **⋮ → 翻页提前量** 打开的弹窗，
  里面是 `− 值 ＋` + ms 输入框；单击 ±100ms，长按 100ms 连发（首延迟 300ms），松手吸附 50ms 网格。
- **打点页**：顶栏 56（完成按 `validate` 结果在实心/玻璃之间切）→ 预览 → 工具行 44（撤销/重做 … 选中胶囊+取消）
  → 播放行 36 → 微调行 40（选中才出现）→ 时间轴 116 → 底栏（添加第 N 页占 2/3 带页码色点，更多固定 104）。
- **首页**：标题撑满 + 排序 44 圆 + 「＋」玻璃胶囊（**只留 + 图标，不写「新建」**，见第四批）；
  网格 **`GridCells.Fixed(2)`**（原来 `Adaptive(168)` 在 360dp 屏算出来是 1 列，这才是「整屏巨幅方块」的根因）；
  列表右侧有快速定位滑块（`WpScrollBar`）；筛选/排序菜单选中项**不打钩**，只靠强调色 + Medium 字重。
- **播放列表首页**（2026-10-25 调整）：**点整行 = 直接开始播放这个列表**（从第 1 首起）；
  右侧 `⋮` 菜单 = 编辑 / 导出 .wplist / 删除（删除过确认弹窗）；长按仍是多选批量导出/删除。
  编辑页**不再从点行进入**，唯一的入口是 ⋮ → 编辑。右上角「＋」同样只剩图标；行首 46dp 方块
  显示**列表里第一首「可用」项目的封面**（`CoverView` + `rememberCoverBitmap`，没有可用项目就是占位色）；
  同样挂 `WpScrollBar`。
- **播放列表编辑页**：结构不变，底部仍保留「开始播放」实心键（和点行开播并存，
  两个入口共用 `AppRoot.startPlaylist()`）；左上角返回是 `IconBack` 细 chevron（原来是文字「←」）。
- **播放列表行（编辑页里的曲目行）**：长按整行拖动排序（拖动中抬升 + 跟手位移，松手才换位），
  把手是纯视觉提示，右侧只留一个删除图标，行内可点区域 5 → 3。
- **底栏 tab**：三个 tab 之间**可以横向滑动切换**（`HorizontalPager`，`beyondViewportPageCount = 2`
  让三页都保持组合，滑回来时搜索词/滚动位置还在）。点底栏 ↔ 滑动两边共用 `pagerState`：
  `tab` 变 → `animateScrollToPage`；手势翻页 → 等**滚动停稳**（`isScrollInProgress == false`）后
  用 `snapshotFlow` 回写 `onTabChange`，且必须经 `rememberUpdatedState(tab)` 读最新值。
  ⚠️ 别按 `currentPage` 实时回写：从第 0 页点到第 2 页会途经第 1 页，实时回写会把 tab 改成 1，
  `LaunchedEffect(tab)` 的 key 一变就**取消了正在跑的滚动动画**，pager 卡在两页之间（见踩坑表）。
  选中块的横坐标 = `currentPage + currentPageOffsetFraction`，走 `Modifier.offset {}` 的 lambda 版本
  （只重排不重组），所以**手指拖到一半时那块底停在两格之间**，松手才吸附。文字色仍 180ms 过渡。
  注意：滑动时子级手势优先（设置页的 Slider、搜索框的横向拖动不会被 pager 抢走）。

| 滚动条滑块位置整体偏下、拖到底跑出屏幕 | 滑块和列表不同步：列表在顶部时滑块在中间，列表到底时滑块有一半在屏幕外 | 容器是 `contentAlignment = CenterEnd` + `Modifier.offset { }` → 子项**先被垂直居中，再叠加位移**，等于多走了半个 (trackH − thumbH)。对齐必须给 `TopEnd`（水平仍是靠右，视觉不变），offset 才是从顶部起算 |
| 滚动条**慢速拖动时上下抽搐** | 拖一点点刻度，列表来回跳；松手瞬间滑块还会回弹一下 | 四个原因叠在一起，都在 `WpScrollBar`：① `可滚项数 = total − visible` 里的 `visibleItemsInfo.size` 会随滚动在 8/9 之间变，同一手指位置上一帧算出第 6 项、下一帧第 5 项 → **按下瞬间冻结分母**；② 滑块位置靠 `firstVisible` 反算，永远慢一帧 → **拖动期间滑块直接跟手指**（`dragTopPx`）；③ 按下就无条件跳到手指位置 → 改**增量拖动**（记住 `grab` 偏移，按在滑块上不跳）；④ 松手立刻交还位置，而最后的 seek 还没落地 → **延迟 120ms 再交还**。另外滑块长度也要冻结（`frozenThumbPx`），否则 `visibleCount` 一变滑块自己抽一下 |
| 滚动条拖动「一下子跳一个卡片」 | 抽搐治好后能拖了，但慢拖也没用——一格一格蹦，落不到两个卡片中间 | 之前 seek 只给 `scrollToItem(index)`，**整项对齐**，手指在两格之间的连续位移全被丢弃。改成亚项精度：`WpScrollBar` 加 `stridePx`（一行占多少像素），把浮点位置拆成 `floor(pos)` 项 + `(pos − index) × stride` 像素偏移，回调改成 `onSeek: suspend (index: Int, offsetPx: Int) -> Unit`，消费端 `scrollToItem(index, offsetPx)`。绘制端也要跟着连续：`continuousFirst = firstVisible + (firstVisibleOffsetPx / stridePx).coerceIn(0f, 0.999f)`。`stridePx` **别用「卡片高 + 行间距」自己拼**（`IntSize.height` 加 `Dp.toPx()` 容易踩 `DpRect.height` 的重载坑，且算不进 `Arrangement.spacedBy` 的误差）——直接量可见项：列表取 `infos[0].offset` 与第一个 `offset` 不同的项的差；**网格要先跳过同行的其他列**（同一行多列 `offset.y` 相同），否则差值是 0 |
| 不动滑块、只用手指滚列表时，**滑块长度一突一突**，停手又"恢复" | 滑块长度跟着列表高度变，滚动过程中一会长一会短，像在呼吸 | 长度是按 `visibleItemsInfo.size` 算的，而它是**离散**的：某项刚探进视口底部 +1、刚完全离开顶部 −1，正常滚动时几乎每帧在 8/9 之间翻。→ 改用**连续**的「视口里装得下几项」= `viewportPx / stridePx`（取 `layoutInfo.viewportSize.height`，滚动中恒定），滑块长度就锁死了。顺带把位置分母和拖动目标的分母**也换成这个浮点值**——之前用整数 `total − visible`，会让「滑块画在哪」和「拖到哪」差一格 |
| 拖滚动条时**卡片来回抽搐** | 拖动中卡片往前一点又弹回来，锯齿式抖，越慢越明显 | 滚动位置曾按 **item 单位**算：`pos = 分数 × (total − 一屏项数)`，再拆 `index = floor(pos)` + `offsetPx = 小数 × stride`。1 列列表没问题，**2 列网格就废**：第 0、1 项在**同一行**，`scrollToItem(0,0)` 和 `scrollToItem(1,0)` 落点一样，于是 pos 每跨一个整数目标就退回上一行，序列变成 `0 → 0.5行 → 0 → 0.5行 → 1行 → 1行…`。根因是**滚动位置属于"行"域，item 索引不是行索引**。→ 全程改像素/行域：`rows = ceil(total / itemsPerRow)`、`scrollPx = 行号 × stride + firstVisibleOffsetPx`、`fraction = scrollPx / (rows×stride + padding − viewport)`；反算 `row = floor(targetPx / stride)`、`index = row × itemsPerRow`（**永远取行首项**）。这样 `row×stride + offset` 恒等于 `targetPx`，既单调又精确，松手接续也不跳。`itemsPerRow` 由调用方给（列表 1、网格 `GRID_COLUMNS`），项目页的列数已提成常量，和 `GridCells.Fixed` 共用 |
| 拖到底还有一截到不了 | 滑块拖到最底，列表还差一行左右没滚完 | 「能滚多远」只算了 `行数 × 行高`，漏了 `contentPadding` —— 项目页底部留了 110dp 给浮动栏，这段也是实打实的滚动范围。→ `WpScrollBar` 加 `verticalContentPaddingPx`，`contentPx = rows × stride + padding`。播放列表页上下各 4dp，影响可忽略但一并传 |

**关于 15（后台播放）为什么砍掉**：播放页 `keepScreenOn` 默认开，演出场景根本不熄屏，原目标场景已被覆盖；
而 Android 8+ 要做后台播放**必须**起前台服务、前台服务**必须**挂通知，「后台播放」和「通知栏」拆不开。
代价是重写 `player/AudioPlayer.kt` + 改 `PlaybackScreen.kt`（1122 行，全工程最复杂）的播放器生命周期与曲间遮罩状态机，
风险最高、收益最低。真要重启这条，先推翻决策 10。

**关于 17（多色主题）的取舍**：现在颜色是分散硬编码的（`0xFF9EC5FF` 蓝色在按钮、圆点选中环、进度条里各写了一遍）。做之前要先把它们收敛成一套 token（强调色 / 玻璃填充 / 边框 / 文字层级），然后主题只改 token。建议先做「只换强调色」的轻量版，跑一阵看效果再决定要不要往下沉。17 和 18 本质是同一件事，应该合并成一个「外观」模块，用同一套 token 驱动。
