## 1. 产品定位

**Wherever Play** 是一款「伴奏播放 + PDF 谱面自动翻页」的 Android 应用。

用户在音频时间轴上标注「第 N 页应该出现在第几秒」，播放时音频进度跨过标注点即自动切换 PDF 对应页，从而让演奏者/演唱者无需空出手翻谱。

本质：**一条音频时间轴驱动一份 PDF 的页码切换。**

设计取向：
- 纯本地、零联网、无广告、无账号体系。
- 演奏态优先：全屏谱面、深色、防误触、屏幕常亮。
- **打点页对标剪映手机版**：版面、词汇、手势与其剪辑页保持一致。
- **主界面为液态玻璃美学（Liquid Glass）**：半透明玻璃层叠于自定义背景图之上，转场平滑。

## 2. 核心数据模型

```
Project（项目）── App 的基本单元
├── id           : UUID（全局唯一，用于跨设备导入时去重）
├── name         : 项目名（用户自定义）
├── author       : 作者（用户自定义，可为空）
├── cover        : 封面图（本地文件引用）
│                  来源优先级：① 用户从相册选择 ② 音频文件内嵌封面 ③ 占位图
├── audio        : 音频文件引用（mp3 / wav / flac，时长 ≤ 30 分钟）
├── pdf          : PDF 文件引用
├── pageCount    : PDF 页数（创建时读取，只读）
├── marks[]      : 打点列表 { page, timeMs }
│                  约束：page ∈ [1, pageCount]，每个 page 恰好出现一次
│                        timeMs 按 page 顺序严格递增
│                  marks[0] 固定为 { page: 1, timeMs: 0 }
│                  存储：独立表 MarkEntity(projectId, page, timeMs)，不用 JSON 字段
│                        （为未来加批注/循环区间等字段预留，见 §18.4）
├── waveform     : 音频峰值缓存（波形数据，首次生成后落库）
├── isFavorite   : 是否收藏
├── createdAt / updatedAt / lastOpenedAt
└── configured   : 是否已完成打点

Playlist（播放列表）
├── id / name / cover
├── items[]      : 有序的 Project 引用列表
└── advance      : 衔接策略 { mode: tap|auto, gapMs, fadeMs }

AppSettings（应用设置，DataStore）
├── theme / accentColor / fontScale / backgroundImage
├── pageTurnOffsetMs / pageTurnAnimation / keepScreenOn / defaultVolume
└── glassBlurEnabled（低端机可关）
```

**关键约束（v1）**
- 一个 Project = 恰好 1 个音频 + 1 份 PDF。
- **页序严格递增**：最小间隔 300ms，`[t_N, t_{N+1})` 即第 N 页的显示区间。
- 同一页在时间轴上只出现一次。`marks` 结构预留重复 page 的扩展能力，v1 UI 不开放。
- 页码顺序 = 时间顺序，故第 N 个点永远是第 N 页。

## 4. 流程一：新建项目

```
主界面 → [+ 新建项目] → 新建项目页
   ├─ 选择音乐文件（SAF，过滤 mp3/wav/flac）
   │     校验：时长 ≤ 30 分钟，超限拒绝并提示
   ├─ 选择 PDF 文件（SAF，application/pdf）
   │     校验：可解析 → 读出 pageCount；加密/损坏 → 提示不支持
   ├─ 名称：默认取音频文件名去扩展名，可改
   ├─ 作者：默认取音频标签（ID3 artist），可改，允许留空
   ├─ 封面：默认自动提取音频内嵌封面
   │     提取失败 → 显示占位图，并提示「可从相册选择」
   │     用户可随时从相册（Photo Picker）更换，支持正方形裁剪
   └─ [确定]
        ├─ 复制音频 / PDF / 封面到私有目录
        ├─ marks = [{ page: 1, timeMs: 0 }]
        ├─ 后台生成波形缓存
        └─ configured = false → 回主界面
```

**封面提取实现**：`MediaMetadataRetriever.getEmbeddedPicture()` 优先（mp3/flac 命中率高），
失败再手工解析 ID3v2 `APIC` 帧与 FLAC `PICTURE` block。wav 通常无内嵌图，直接走占位图。
封面统一裁成正方形，缓存三档缩略图（128 / 256 / 512）供列表与详情使用。

**年份/标签**：v1 不做（见 §15）。

## 5. 流程二：打点（时间轴编辑器）★核心交互，对标剪映手机版

### 5.0 设计原则

整页版面、元素命名、手势习惯全部向**剪映手机版的剪辑页**看齐。
用过剪映的人打开这一页，应该能不做任何思考就开始操作：中间看画面、下面拖轨道、顶上点完成。

### 5.1 版面结构（自上而下）

| 区域 | 内容 | 剪映对应物 |
|---|---|---|
| 顶栏 | ← 返回 · 项目名 · ↺ 撤销 / ↻ 重做 · **完成** | 剪辑页顶栏（「导出」位置换成「完成」） |
| 预览窗 | 实时显示**播放头所在时刻对应的 PDF 页** | 播放器预览窗 |
| 播放控制行 | ▶/⏸ · 当前时间 / 总时长 · 全屏 | 预览窗下方控制条 |
| 时间轴 | 刻度尺 + **固定中央播放头** + 页片段轨道 + 音频波形轨道 | 时间轴轨道区 |
| 底部工具栏 | 添加翻页 · 微调 · 切页 · 试听 · 更多 | 一级工具栏 |

### 5.2 固定播放头 + 轨道滚动（与剪映完全一致）

- 播放头是**固定在时间轴正中的白色竖线**，移动的是轨道。
- 播放时轨道随时间自动滚动，播放头始终停在同一屏位置。
- 单指在轨道区左右拖动 = 平移时间轴；双指捏合 = 缩放，锚点为捏合中心。
- 缩放范围 **1x – 40x**；实时显示当前可视区间（如 `12:00 – 12:40`）。
- 缩放过小时圆点内不再显示数字，靠颜色 + 大小区分。

### 5.3 轨道

**页片段轨道（唯一一条）**
- 每页占据 `[t_N, t_{N+1})`，渲染为一个片段：内含该页页码（放大后可显示缩略图）。
- 相邻片段的分界线 = 翻页时刻，分界线顶端压一个带页码的圆点（圆点在上、片段在下，向下有小尖角）。
- 片段不可重叠、不可穿越，由严格递增约束保证。

**不做音频波形轨道**（用户 2026-10-24 决定移出 v1）：
省掉首次进入时的预解码等待（3–15s）与相应复杂度，v1.1 再评估。

### 5.4 操作（沿用剪映手势）

| 操作 | 行为 |
|---|---|
| 添加翻页 | 点「添加翻页」→ 在**播放头所在时刻**插入第 N 页的翻页点。若播放头早于最后一点，退化为「最后一点 + 1s」 |
| 拖动 | 按住圆点或片段边界左右拖动 = 修改该页起始时刻；浮出时间气泡（含毫秒） |
| 严格递增夹紧 | 拖动范围夹在 `[前一点 + 300ms, 后一点 − 300ms]`，不能穿越邻居 |
| 微调 | 选中分界点后工具栏切换为二级菜单：`−1s / −0.1s / +0.1s / +1s`，吸附 0.1s 网格 |
| 撤销 / 重做 | 顶栏常驻，覆盖添加/拖动/微调 |
| 完成 | 校验页数齐全，否则提示「还有 N 页未打点」 |
| 页数已满 | `+` 置灰，点击提示「所有页面已创建」 |
| 删除圆点 | v1 无入口；「重新打点」可整体重来 |

### 5.5 预览窗逻辑

- 预览内容 = 播放头时刻 `t` 对应的页：取 `marks` 中 `timeMs ≤ t` 的最后一个点。
- 打点未完成时同样成立（未打的部分停留在前一页）。
- 播放时预览窗随音频**实时翻页**，直接回答"第几秒音乐放的是什么"。
- 点预览窗 = 全屏查看当前页（可捏合放大），再点返回。
- **手势（v1 新增）**：
  - 双指捏合缩放，范围 1x–5x，锚点为捏合中心；
  - 单指拖动平移（仅在已放大时可拖，避免与点击全屏冲突）；
  - 双击 = 复位到适配宽度；
  - 切到新页时自动复位缩放，避免上一页的放大状态被带过来。

### 5.6 内置播放

- 完整播放器：播放 / 暂停 / 拖动定位 / 从头播。
- 播放时轨道自动滚动 + 预览窗自动翻页，形成「听着听着，到该翻的地方按一下添加翻页」的闭环。

### 5.7 刻意与剪映不同的地方

| 项 | 剪映 | 我们 |
|---|---|---|
| 轨道数 | 多轨 | 2 条（谱面页 + 音频） |
| 主操作 | 导出成片 | 完成（写回项目配置） |
| 时间轴元素 | 片段可任意拉伸 | 片段长度由相邻翻页点决定 |

## 6. 流程三：播放页（电子书式全屏阅读模式）

```
主界面 → 点击项目
   ├─ configured == false → 打点页（提示「未进行时间轴匹配」）
   └─ configured == true  → 播放页
```

### 6.1 版面：极简，只留一条控制栏

```
┌────────────────────────────┐
│                            │
│        全屏谱面             │  ← 沉浸式：状态栏隐藏
│     （左右滑动翻页）         │
│                            │
├────────────────────────────┤
│ ━━━━━━━●──────────── 0:13  │  ← 进度条 + 时间
│        [▶ / ⏸]             │  ← 只留播放/暂停
└────────────────────────────┘
```

- 顶栏默认**不显示**（没有"返回/页号/重新打点"常驻按钮）。
- 底部只保留：进度条 + 播放/暂停。
- 右上角一个「**⋯**」按钮，收纳全部次要功能（见 6.4）——平时半透明，点谱面中央时与之一起显隐。

### 6.2 翻页模型（关键：手动与自动如何共存）

| 事件 | 行为 |
|---|---|
| 音乐跨过打点 | **自动跳转**到该打点对应的页 |
| 左右滑动谱面 | **手动翻页**：只改"当前显示页"，**完全不影响音频播放**（不暂停、不跳转） |
| 手动翻页后 | 进入「手动覆盖」状态，页面停在用户翻到的位置，直到下一个打点到来 |
| 下一个打点到来 | 退出「手动覆盖」，跳到该打点的页 |
| 双击谱面 | 立即回到"当前时刻应有的页"（取消手动覆盖） |

**示例**：音乐在第 4 页区间，用户右滑到第 5 页看后面的段落 →
音频继续播；当音乐走到「第 5 页」的打点时，页面本来就是第 5 页，无跳变；
当走到「第 6 页」的打点时，跳到第 6 页。

- 手动翻页的边界：第 1 页再左滑、最后一页再右滑 → 不做动作（轻微回弹）。
- 滑动一屏 = 翻一页；不做连续滚动（与"自动翻页=整页切换"保持一致）。
- 手动翻页时，预渲染需要覆盖到"用户可能滑到的相邻页"，否则滑动会白屏 —— 实现上滑动结束后立即请求该页渲染。

### 6.3 谱面手势

| 手势 | 行为 |
|---|---|
| 左右滑动 | 翻上一页 / 下一页 |
| 双击 | 回到当前打点对应的页（取消手动覆盖） |
| 单击画面中央 | 显示 / 隐藏控制栏与「⋯」（沉浸切换） |
| 双指捏合 | **不做**（演奏时误触代价太高，阅读模式保持固定缩放） |

### 6.4 「⋯」菜单收纳的内容

- 翻页提前量（±500ms）
- 翻页动画（无 / 淡入淡出 / 滑动）
- 屏幕常亮开关
- 重新打点
- 返回项目列表

### 6.5 其他能力

- **预渲染**：当前页 + 下一页 + 上一页（LRU 24MB），并按 4.2 的"提前量"提前渲染。
- **后台播放**：MediaSessionService + 前台服务 + 通知栏；熄屏继续播。
- **保持常亮**：演奏时不熄屏。

v1 不做：变速、变调、A-B 循环（音频管线按可插拔设计预留）。
> **变速已彻底取消，不列入任何后续版本**：伴奏变速会引入相位不连续与瞬态模糊，真实乐器录音上劣化明显（见 §18 关键判断）。

## 7. 流程四：播放列表 / 串烧

- 编辑页：从项目库勾选加入、拖动排序、移除、重命名、删除、设置封面。
- 播放页：按序播放各项目的音频 + 各自 PDF。
- 衔接策略（已定）：
  - 默认「一首播完暂停，点击屏幕再开始下一首」。
  - 可选「暂停 N 秒后自动播放下一首」（默认 3s）。
  - 可选淡入淡出（默认 1.5s；淡出需在曲末前 N 秒启动音量斜坡）。
- 跨项目跳转：上一首 / 下一首，同步切换音频与 PDF。
- 同一项目可被多个列表引用；同一列表内不重复。
- **失效项处理（用户已定）**：关联项目被删除后，该条目立即变灰、显示为不可用。
  实现上保留为**占位项**（不静默删除），原因：
  - 保留它在列表中的位置与顺序，用户看得见"这里少了一首"而不是列表莫名变短；
  - 项目 UUID 与媒体 sha256 均稳定，用户日后**重新导入同一项目可自动重新绑定**；
  - 播放到该项时跳过并轻提示，不中断整场演奏。
  - 列表卡片显示「N 项不可用」角标；编辑页提供「移除失效项」一键清理。

## 8. 项目 / 播放列表的打包与传播

### 8.1 容器格式

统一 **ZIP 容器，扩展名 `.wplay`**，MIME `application/x-wherever-play`。

```
曲名.wplay  (ZIP)
├── manifest.json
├── media/
│   ├── <sha256前16>.mp3
│   ├── <sha256前16>.pdf
│   └── <sha256前16>.jpg        # 封面
├── projects/<projectId>.json
└── playlists/<playlistId>.json
```

```json
{
  "magic": "WPLAY",
  "formatVersion": 1,
  "kind": "project" | "playlist",
  "title": "肖邦练习曲",
  "author": "Chopin",
  "cover": "media/9f2c….jpg",
  "exportedAt": "2026-10-24T17:00:00+08:00",
  "appVersion": "1.0.0",
  "mediaIncluded": true,
  "projects":  [{ "id": "uuid", "name": "曲名", "file": "projects/uuid.json" }],
  "playlists": [{ "id": "uuid", "name": "演出曲目", "file": "playlists/uuid.json" }],
  "files": [{ "path": "media/ab12….mp3", "size": 5242880, "sha256": "…" }]
}
```

### 8.2 播放列表包必须自包含（关键决策）

播放列表要能被**传给另一个人**并直接可用，就必须自包含；否则接收方拿到的是一堆断链引用。
- 项目包 = 音频 + PDF + 封面 + 打点信息。
- 播放列表包 = 其引用的全部项目（含媒体）+ 列表结构 + 衔接策略。
- 体积：10 首 320kbps mp3 ≈ 100–150MB，导出前显示预估。
- v1.1 预留 `mediaIncluded: false` 轻量包（只传打点与结构，按 sha256 匹配本地已有音频）。

### 8.3 轻量化与模块化

| 手段 | 效果 |
|---|---|
| 内容寻址文件名（sha256 前 16 位） | 同一音频多项目共用 → 包里只存一份；导入时命中本地则复用 |
| 项目/列表拆成独立 JSON | 导入可按对象粒度勾选，满足「只导入列表里的某几个项目」 |
| `formatVersion` | 未来格式升级可迁移 |
| manifest 内 sha256 清单 | 完整性校验，定位损坏文件 |

### 8.4 导出流程

项目卡片菜单 / 项目详情 / 播放列表页 →「导出」→ 显示体积 → SAF 保存（默认 Download，`<名称>.wplay`）→ 可调起系统分享面板（微信/QQ）。

### 8.5 导入流程

```
入口 = 主界面「+ → 导入文件」 或 外部 Intent 用本 App 打开 .wplay
   ↓ 内容探测（不依赖扩展名，微信会改后缀）：ZIP → manifest.json → magic == "WPLAY"
   ↓ 导入预览页（勾选清单）
   │   ├─ 共 N 个项目、M 个播放列表、总体积
   │   ├─ 每项：封面 / 名称 / 作者 / 时长 / 页数 / 是否已存在
   │   ├─ 勾选要导入的对象（默认全选）
   │   └─ 冲突：同名 → 覆盖 / 保留两份 / 跳过
   ↓ 校验 sha256 → 媒体去重复用 → 写库 → 刷新
```

- **必须注册 Intent Filter**（`.wplay` + `application/x-wherever-play`），使微信/QQ 收到后可「用 Wherever Play 打开」。

## 9. 文件存储

| 内容 | 位置 |
|---|---|
| 音频 / PDF / 封面正本 | 私有目录 `files/media/`，内容寻址命名 |
| 封面缩略图 | `cache/thumbs/`，可重建 |
| 项目 / 列表 / 设置 | Room + DataStore |
| 波形峰值 | Room（每项目一行 byte array） |
| 页图缓存 | `cache/pdf/`，LRU 清理 |
| 日志 | `files/logs/`，滚动保留 7 天 / 单文件 2MB |

## 11. 视觉设计规范：液态玻璃（Liquid Glass）

### 11.1 玻璃层叠 token

| token | 深色主题 | 说明 |
|---|---|---|
| `glass.fill` | `white α 6%–10%` | 玻璃主体填充 |
| `glass.border` | `white α 20%`，0.5dp | 边缘细描边 |
| `glass.highlight` | 顶部 1dp，`white α 24% → 0` | 顶面反光，唯一允许的渐变 |
| `glass.blur` | 24dp（可关） | 背景模糊半径 |
| `glass.shadow` | 无（用描边与明度区分层次） | — |
| 圆角 | 卡片 16–20dp；胶囊 = 高度/2 | — |

### 11.2 实现方案与硬约束

- **背景模糊**：Compose 的 `Modifier.blur()` 只能模糊自身内容，无法采样背后壁纸。
  用成熟方案做 backdrop blur（`dev.chrisbanes.haze`），把背景图与滚动内容画在玻璃层之下再取景。
- **API 分级降级**：
  - Android 12+（API 31+）：真实模糊。
  - API 24–30：降级为「半透明 + 更强描边 + 顶部高光」，无模糊。视觉近似，不崩不卡。
- **性能红线**（必须遵守，否则列表会掉帧）：
  - 同屏同时存在的实时模糊层 ≤ 2 层。
  - 列表滚动过程中，卡片玻璃层使用静态缓存，滚动停止后再恢复实时模糊（或直接常关）。
  - 设置里提供「玻璃模糊」总开关。
- 不做真正的光学折射（需 AGSL `RuntimeShader`，API 33+ 且功耗高），v1 不引入。

### 11.3 转场动效

- 底部 tab 切换：`AnimatedContent` + 横向位移 30% + 淡入，260ms，emphasized 曲线。
- 项目卡片 → 播放页：`SharedTransitionLayout` 容器变换，封面从卡片位置放大到谱面区，300ms。
- 打点页 ↔ 播放页：淡入淡出，避免打断演奏心流。
- 所有动效遵循系统「移除动画」无障碍设置。

### 11.4 主界面版式

## 13. 圆点配色（已定）

**黄金角色相**：`hue = ((页码 − 1) × 137.508°) mod 360°`，固定 S≈0.52 / V≈0.96。
任意页数下相邻两页色差恒定，不会出现「第 8 页和第 1 页同色」。

状态优先于颜色：当前页圆点放大 + 白环；片段被选中时描边高亮；页码在空间足够时始终显示。

## 17. 轻量化预算与取舍（用户要求逐项评估）

### 17.1 硬性预算

| 指标 | 目标 |
|---|---|
| APK 体积（不含用户媒体） | ≤ 15 MB |
| 主界面滚动 | 稳定 60fps（中端机） |
| 播放页内存峰值 | ≤ 120 MB（3 页位图 + 解码器 + 播放器） |
| 单项目磁盘占用 | 媒体正本 + ≤ 1 MB 附属数据（封面、波形、缓存） |
| 冷启动到主界面可交互 | ≤ 1.2s |

### 17.2 各项功能的真实成本与处置

| 功能 | 存储成本 | 性能成本 | 收益 | 处置 |
|---|---|---|---|---|
| PDF 页位图 + 3 页预渲染 | 内存 6.6MB/页（ARGB_8888） | 中等，但翻页必需 | **必须有**，否则"声音到了谱没翻" | 位图**必须 ARGB_8888**（PdfRenderer 硬性限制，传 RGB_565 会直接抛异常），所以内存只能靠「限制渲染宽度为屏幕宽度 + 缓存上限 24MB」来控 |
| 液态玻璃实时模糊 | 额外全屏纹理约 10MB | **高**，低端机可能 30fps | 高（颜值） | **只在主界面启用**；播放页/打点页用纯深色；列表滚动时冻结模糊；提供总开关 |
| 音频波形 | 4KB / 项目 | 首次解码 3–15s（后台） | 极高（看乐句找翻页点） | 保留，改为**首次进入打点页时才生成**，不在创建项目时抢资源 |
| 主界面背景图 | 磁盘约 2MB | 解码约 8MB 内存 | 中（个性化） | 保留，但长边限 **1920px**（原 2560 下调） |
| 封面三档缩略图 | 磁盘 ×3 | 生成耗时 | 低 | **砍成一档**，其余交给 Coil 内存缓存 |
| Hilt | 约 300KB APK | 无 | 开发效率 | 保留，R8 后影响可忽略 |
| 日志 | 原 14MB（2MB×7） | 无 | 排障 | 收紧到 **单文件 1MB / 保留 7 天 / 上限 5MB** |
| 导出/导入打包 | 临时占用 = 包体积 | 一次全量 IO | 必须 | 流式写入，结束立即清理临时目录 |

### 17.3 建议主动砍掉的三项

1. **独立「数据库管理」页面** —— 功能并入项目页（筛选、排序、长按多选批量删除/导出）与设置页的存储统计。少一个页面、少一套交互。
2. **三档封面缩略图** —— 只生成一档磁盘缓存，显示尺寸由 Coil 按需采样。
3. **全局液态玻璃** —— 仅在主界面使用。演奏态（播放页、打点页）本来就需要纯黑背景看谱，玻璃在那儿既无用又费电。

## 18. Demo 范围（第一版可运行原型）

### 19.1 Demo 的唯一目标

证明一句话：

> **导入伴奏和谱子 → 打完点 → 按播放 → 谱子自己翻，而且翻得及时。**

Demo 不承担"好看""完整""可分享"的职责，只承担"这件事在真机上真的成立"。

### 19.2 验收标准（三条，缺一不可）

1. 用一首 3–5 分钟伴奏 + 一份 5 页 PDF，从零到打完点 **≤ 3 分钟**。
2. 播放中 5 次翻页 **肉眼无迟滞、无错页**（含连续快速翻页）。
3. 杀掉进程重新进入，项目与打点 **仍在**。

### 19.3 必须进 Demo

| 功能 | 为什么不可省 | 复杂度 |
|---|---|---|
| 新建项目：SAF 选音频 + 选 PDF + 命名 | 没有它就没有任何数据 | 小 |
| 项目列表（纯文字卡片，无封面无玻璃） | 唯一入口 | 小 |
| 打点页（简化版）：播放/暂停 · 线性进度条 · 圆点拖动 · 微调 ±0.1s/±1s · 「在此处添加第 N 页」· 完成校验 | 核心，且验收标准 1 靠它 | 中 |
| 播放页：全屏谱面 · 自动翻页 · **预渲染下一页** · 翻页提前量 · 边缘点击手动翻页 · 屏幕常亮 | 核心，验收标准 2 靠它 | 中 |
| 持久化：Room 最简三表（Project / Mark）+ 媒体复制进私有目录 | 验收标准 3 | 中 |
| 状态提示：「未打点」标记、页数不足报错 | 否则演示时会误以为 App 坏了 | 小 |

### 19.5 Demo 必须验证的三个技术风险

这三件事如果 Demo 阶段不测，v1 会推倒重来：

| 风险 | 要测什么 | 不测的后果 |
|---|---|---|
| **翻页迟滞** | `PdfRenderer` 单页渲染实测耗时（分别测矢量谱 / 高清扫描谱）；验证「预渲染下一页 + 提前量」能否做到肉眼无感 | 声音到了谱还没翻，产品直接失败 |
| **同步精度** | 播放位置与翻页触发的实际误差区间（轮询频率 vs 帧同步） | 翻页早半拍或晚半拍，无补偿手段 |
| **内存上限** | 3 页 RGB_565 位图 + 播放器在中低端机的峰值内存 | 演奏到一半 OOM 崩溃 |

### 19.6 Demo 的代码策略（避免白干）

| 模块 | 策略 |
|---|---|
| 数据层（Room 实体 / Repository） | **按最终架构写**，可保留 |
| PDF 渲染器（含预渲染与缓存） | **按最终架构写**，可保留 |
| 播放器封装（Media3） | **按最终架构写**，可保留 |
| 时间轴组件 | 写**简化版**（线性进度条 + 圆点），代码内明确标注 `DemoTimeline`，v1 换为剪映式 Canvas 时间轴 |
| 全部 UI 视觉 | **不做美化**，纯 Material 默认组件 |

原则：**能长期留用的模块一次写对，只有时间轴这一块允许写"临时版"。**
