# Wherever Play · 设计上下文（压缩版）

> 只保留设计判断需要的信息。技术实现细节、代码行号、构建配置一律不在此文档。
> 上游依据：`docs/交接文档.md`、`docs/功能想法与修复清单.md`、`ui/*.png`（现有实机截图）。

## 1. 产品一句话

Android 本地 App：选一首伴奏 + 一份 PDF 谱，在时间轴上逐页打点，播放时谱面按时间自动翻页。演出场景，双手在乐器上，屏幕不能频繁碰。

## 2. 设计约束（长期有效）

- **不改美术风格**：暗底、静态玻璃（白 8%~15% 填充 + 0.5 描边）、强调色 `#9EC5FF`、圆角体系、字体全部沿用现有实现。
- 只改：按钮归属 / 位置 / 尺寸 / 分组与层级 / 触控热区 / 动效参数。
- 画板基准 390×844 dp（主流机型 360dp 宽也须成立）。
- 热区 ≥ 44×44；视觉可以更小，用「44 容器 + 34 视觉」实现。
- 图标全部自绘（工程未引 material-icons），所以图标必须是能徒手画的简单几何。

## 3. 核心设计方法：按钮三层

按「操作频次 × 后果严重度」分层，同层才允许共处一条视觉带。

| 层 | 判据 | 表现 |
|---|---|---|
| 主操作 | 高频 + 是当前页面目的 | 实心高对比，一屏仅一个 |
| 次操作 | 中频 | 玻璃填充 + 描边，同带最多 3 个 |
| 低频 / 破坏性 | 误触代价高 | 收进「更多」或移出主视觉带 |

现有三个页面乱在三处：菜单项平铺 8 个（意图混排）、顶栏挤 5 个控件（层级不分）、图标按钮同权且热区不足 44。

**动效 6 条**（均含 3 关键帧 + 曲线）：

1. 跟手翻页：拖动 1:1 无缓动；松手判定 > 12% 屏宽或（> 5% 且速度 > 0.55 px/ms）；回弹 160ms / 翻页 220ms，`cubic-bezier(0.2,0,0,1)`；翻完直接归零，不做第二段。
2. 控制栏显隐：单击谱面区，顶底两条同时淡入 + 上移 4dp，180ms，`cubic-bezier(0.4,0,0.2,1)`；淡出只改透明度；不改谱面尺寸；连点合并。
3. 按压反馈：scale 0.96 / 90ms → 回 1.0 / 140ms spring(600, 0.85)；圆形按钮加 12% 白环外扩淡出 120ms；只缩不放。
4. Tab 切换：选中块滑动 320ms spring(380, 0.82)，文字色 180ms 同步；保留各自滚动位置。
5. 打点添加：圆点 0.4→1.0 / 220ms spring(380, 0.7) + 色环外扩淡出 240ms；选中仅外环 180ms 不变色；撤销反向缩到 0 / 140ms。
6. 曲间遮罩：200ms 淡入，底图为下一首第 1 页；倒计时数字每 1000ms 脉冲 1.0→1.06→1.0；点屏即切，切歌无转场。

## 5. 硬约束（做设计时别踩）

- 第 1 页必须锁在 0:00，打点最小间隔 300ms → 时间轴第 1 个圆点不可拖。
- 播放页手动翻页不影响音频，下个打点自动跳回；设计上不要出现「手动翻页即暂停」的暗示。
- 时间轴拖动必须冻结可视窗口，只让光标走；否则整个时间轴会跟着滑。
- 拖进度条时必须暂停自动翻页，松手才恢复，否则「拖一下就翻走」。
